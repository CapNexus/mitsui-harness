# Build the A/B/C permission test harness

Build one harness that checks users A, B and C against the access matrix so that every entry point gives repeatable evidence.

## User story

As Soma (solution architect), I want one test harness that runs the same checks as users A, B and C and compares results with the access matrix, so that permission tests give the same evidence through every entry point.

## Acceptance criteria (EARS)

1. When the harness runs with an access matrix, the harness shall generate expected results per user including tables visible and masked column visibility.
2. When the harness runs through direct Athena and through the Gateway, the harness shall compare actual results with the expected results and report each difference.
3. The harness shall obtain tokens interactively at run time and shall not store them.
4. The harness shall use an expected-results file that the Teams, Claude Code and Claude Desktop runs can reuse.
