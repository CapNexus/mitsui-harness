# Launch the Control Tower landing zone with Region-deny exceptions

Launch Control Tower from a manifest kept in the repository so the account structure is repeatable and Region-deny allows the Regions Claude cross-region inference needs.

## User story

As Venkat (DevOps), I want the Control Tower landing zone launched from a manifest kept in the repository, so that the account structure is repeatable and the Region-deny control already allows the Regions Claude cross-region inference needs.

## Acceptance criteria (EARS)

1. When the landing zone is launched, the launch shall use the Control Tower landing zone API with a manifest file stored in the repository, after Venkat and Soma approve the manifest.
2. The landing zone shall use us-east-1 as home Region, and the Region-deny control shall allow us-east-1, us-east-2 and us-west-2.
3. When the landing zone is ready, Control Tower shall have created the Log Archive and Audit accounts from the DEP-03 emails and the Security OU, and the Workloads OU shall exist.
