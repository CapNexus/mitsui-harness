# Verify the next scheduled load recovers after the stopped run

Show that the system heals after the fault test: the next scheduled load completes, row counts match again, and no table is left half-loaded.

## User story

As a Mitsui DBA, I want the data to be whole after a failed load, so that assistant answers are never based on half-loaded tables.

## Acceptance criteria (EARS)

1. When the next scheduled load completes after the stopped run, the system shall report matching row counts between source and target.
2. When the next scheduled load completes after the stopped run, the system shall show `ok` in `wda_meta.load_runs` for every table.
3. When the recovery check completes, the system shall have the `load_runs` query output for that run saved under `evidence/F04/fault-test/`.
