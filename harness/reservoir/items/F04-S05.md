# Load staged files into S3 Tables with a name map

Load staged DMS files into S3 Tables and keep a source-to-target name map so the assistant queries current lowercase Parquet-backed tables.

## User story

As Venkat (DevOps), I want a job that loads the staged DMS files into S3 Tables and keeps a source-to-target name map, so that the assistant queries current, lowercase, Parquet-backed tables.

## Acceptance criteria (EARS)

1. When staged files exist for approved tables, the job shall replace each approved table in S3 Tables with a full load.
2. When the job loads a table, it shall write rows to wda_meta.name_map with database, source schema, source table, source column, target table and target column.
3. If a staged file has no approved row, then the job shall skip it, log a warning and not create the table.
4. The Athena workgroup shall enforce the per-query scan cutoff from athena_scan_cutoff_gb.
