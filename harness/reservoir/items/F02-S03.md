# Build the KMS key and log encryption baseline

Create one customer-managed KMS key for secrets and logs so credentials and audit logs sit under a key Mitsui controls.

## User story

As Venkat (DevOps), I want one customer-managed KMS key that encrypts secrets and logs, so that DMS credentials, audit logs and Bedrock logs are all under a key Mitsui controls.

## Acceptance criteria (EARS)

1. When the baseline stack is synthesized, it shall contain a customer-managed KMS key with rotation on, an alias, and a retain policy on stack deletion.
2. The key policy shall allow Secrets Manager and CloudWatch Logs in the POC account to use the key and shall allow no principal outside the POC account.
3. When a stack creates a secret or log group through the shared baseline helpers, the secret and the log group shall use this key.
